# Формат λ-домашек (`.lam`) — спецификация v2

Язык файлов, которые проверяет `lambda` (пакет `lambda-engine/` в шаблоне домашек).
Один файл — одна домашка или один её блок; проверки исполняет `Test/Lambda.hs`
через обычный HUnit-раннер шаблона, так что статусы `DONE / PARTIAL / FAILED / TODO`,
`make check` и CI общие со всеми домашками (TODO — все проверки задачи упёрлись в
дырку `...`). Уровень задачи — первое число её идентификатора (`1.x` обязательные,
`2.x` к сессии, `3.x` челлендж); файл `TASKS` шаблона задаёт порядок, подписи и
правила «любые k из n» (см. «Инфраструктура» §16.6).

v2 заменяет гипотетическую спецификацию 09.2026: секции вместо перечисления имён
в `task`, единый `TASKS`, типы и константы для hw03, предикаты форм, семейства
обитателей.

## 1. Файл

Файл — последовательность утверждений, по одному на строку. Пустые строки и
комментарии `-- …` игнорируются. Цепочки (`chain`) занимают несколько строк:
продолжения начинаются с пробела.

```
language pure                 -- или typed; должно стоять первым (по умолчанию pure)
import prelude                -- загрузить prelude.lam из того же каталога (можно несколько)
vars x y z                    -- имена, которые в этом файле можно оставлять свободными
```

`language pure` — чистое λ-исчисление; цифры `3` — сокращение для числа Чёрча
⌜3⌝ (`\s z. s (s (s z))`), как ⌜n⌝ на лекции. `language typed` — λ→ с
аннотациями по Чёрчу, базовыми типами `Int`, `Bool`, литералами и примитивами
(§6). Импортируемый файл должен быть на том же языке.

Любое свободное имя, которого нет ни в определениях, ни в `vars`, — ошибка
«не определено» (так опечатка `paier` не даёт молча ответ `paier`).

## 2. Термы

```
\x y. body      λx y. body     \x y -> body     -- три записи абстракции; печатается первая
f x y                                          -- аппликация, левоассоциативна
(t)                                            -- скобки
...                                            -- дырка: место для ответа
[x |-> N] M                                    -- подстановка [x ↦ N] M; только первой строкой chain
\x:a y:(a -> b). body                          -- аннотация по Чёрчу (typed)
3                                              -- pure: ⌜3⌝; typed: литерал Int
```

Имена: буквы (в том числе греческие), цифры, `_`, `'`. `K'` — это K* с лекции.
Тело абстракции тянется вправо до конца строки или закрывающей скобки.

## 3. Определения и задачи

```
name := term                   -- определение («обозначим», как на практике); в теле могут быть дырки
task 1.1 (15 мин)              -- открывает секцию задачи; текст в скобках — для человека
rule any 2 of: 1.1 1.2 1.3     -- дублирует правило из TASKS для читателя; проверялка игнорирует
```

Все утверждения после строки `task` до следующей `task` принадлежат этой задаче.
Определения до первой `task` — общие (как прелюдия). Идентификатор задачи
совпадает с именем теста в раннере и с идентификатором в `TASKS`.

Статус задачи считает раннер: `DONE` — все проверки секции прошли; `PARTIAL` —
часть; `FAILED` — ни одна. Определение с дыркой проваливает каждую проверку, которая
от него зависит, с сообщением «в ‘name’ осталась дырка».

## 4. Проверки (pure и typed)

| Утверждение | Что проверяется |
|---|---|
| `expect A = B` | βη-эквивалентность: обе стороны нормализуются в окружении файла (лимит шагов), нормальные формы η-редуцируются и сравниваются с точностью до α (так `pow 5 0`, то есть `I`, принимается за ⌜1⌝); если нормальной формы нет — ограниченное сравнение головных нормальных форм (деревья Бёма, коиндуктивно: повторно встреченная пара считается равной), поэтому `Y g x = x (Y g)` решается. |
| `free NAME = x y` | множество свободных переменных терма `NAME` равно перечисленному (пустой список — терм замкнут). |
| `rename NAME = term` | `term` α-эквивалентен `NAME`, все его связыватели попарно различны и не совпадают со свободными именами (соглашение Барендрегта) — ответ на «обозначьте, к какому связывателю относится каждая переменная». |
| `minimal NAME = term` | `term` — то же дерево, что `NAME`, и в записи нет лишних скобок (число `(` равно числу в канонической печати). |
| `check NAME: p1, p2, …` | предикаты для терма `NAME` после полного раскрытия имён: `closed`, `whnf`, `hnf`, `nf`, `not p`, `normalizing` (сильная нормализуемость — приближение: нормализуется и в нормальной, и в аппликативной стратегии за лимит), `uses X`, `avoids X` (имя `X` встречается / не встречается в определении и в определениях, от которых оно зависит). |
| `chain …` | цепочка редукций, §5. |

## 5. Цепочки

```
chain NAME [from GIVEN] [to TARGET] [(steps k)] [(strategy normal|applicative)] =
  term0
  ~b~> term1        -- один β-шаг (любой редекс)
  ~K~> term2        -- раскрыто (или свёрнуто) одно вхождение имени K
  =a=  term3        -- α-переименование
  ~eta~> term3'     -- один η-шаг в любом месте терма: \x. M x в M (x не свободна в M) или обратно
  ~~>  term4        -- не более k шагов, β или раскрытий имён (по умолчанию k = 3), поиск по всем редексам
  ~s~> term5        -- выполнена подстановка из [x |-> N] M слева
```

- Раскрытие имени пишется с самим именем в стрелке, как ⇝_K на лекции и практике:
  `~K~>`, `~S~>`, `~K'~>`. Имена `b`, `s` и `eta` заняты стрелками `~b~>`, `~s~>` и
  `~eta~>`, определять их нельзя (η-стрелка пишется словом: однобуквенное `e` студенты
  охотно берут для своих определений). Числа раскрывать не нужно: `3` в цепочке уже означает ⌜3⌝.
- Без `strategy` имена непрозрачны: чтобы сократить `I x`, нужно сначала `~I~>`.
- Со `strategy` обе стороны шага сравниваются после полного раскрытия имён, и `~b~>`
  обязан быть *тем самым* шагом стратегии: `normal` — самый левый внешний редекс,
  `applicative` — самый левый внутренний. `=a=` в этом режиме — просто проверка
  равенства раскрытых термов; `~K~>` проверяется как обычно (одно вхождение `K`).
- `from GIVEN`: первая строка обязана совпадать с `GIVEN` (для задач, где начало
  задано условием). `to TARGET`: последняя строка обязана быть α-эквивалентна
  `TARGET` после раскрытия имён. Без `to` цепочка считается законченной, если в
  последнем терме нет β-редексов (имена в аргументах раскрывать не нужно).
- Ошибка сообщается по строкам: «строка 3 не получается из строки 2 одним β-шагом;
  возможные шаги: …», «строка 4 получается из строки 3 раскрытием ‘I’, а не ‘K’».

## 6. Типы (только `language typed`)

Типы: `a`, `α`, `Int`, `Bool`, `a -> b` (правоассоциативно), скобки. Переменные
типов — строчные имена; в выводе печатаются `α β γ δ …`.

| Утверждение | Что проверяется |
|---|---|
| `type NAME = T` | наиболее общий тип терма `NAME` (по Карри; аннотации по Чёрчу в терме учитываются как заданные) равен `T` с точностью до переименования переменных типов. `type NAME = none` — терм нетипизируем. |
| `church GIVEN = term` | типизация по Чёрчу: стирание аннотаций из `term` α-эквивалентно раскрытому `GIVEN`; `term` типизируется по аннотациям; полученный тип — наиболее общий (совпадает с типом по Карри с точностью до переименования). |
| `inhabit T: n1 n2 …` / `inhabit T: none` | каждый `n_i` замкнут, имеет тип `T` (тип `T` — частный случай его наиболее общего типа), термы попарно αβη-неэквивалентны. |
| `family T: F` | `F ⌜0⌝ … F ⌜4⌝` (числа Чёрча) нормализуются в замкнутые попарно различные термы типа `T` — способ показать бесконечно много обитателей. |

Константы `typed`: литералы `0 1 2 …` : `Int`; `true false : Bool`; `plus minus
mult : Int -> Int -> Int`; `eq lt : Int -> Int -> Bool`; `iszero : Int -> Bool`;
`if : Bool -> a -> a -> a` (примитив срабатывает, когда его аргументы уже литералы, то есть строго, в стиле PCF). В
`pure` эти имена не зарезервированы.

## 7. Сообщения

Проверялка печатает нормальные формы через декодер: числа Чёрча как `⌜6⌝`,
`true`/`false`, пары `⟨a, b⟩`, списки Чёрча `[1, 2]`. Пример: «expect mult 2 3 = 6:
слева получается ⌜5⌝, а справа ⌜6⌝». Стороны названы по месту, а не «получено /
ожидалось»: в `expect or true false = true` ответ студента слева, а в
`expect K I S = ...` справа. `minimal` никогда не печатает терм: канонная печать без
лишних скобок и есть ответ. Сообщения — по-русски, для студента.

Нормальная форма для `expect`, `inhabit`, `family`, `:nf` и `:decode` считается
нормализатором с разделением вычислений (`Lambda.Need`, call-by-need): аргумент и
определение вычисляются не больше одного раза. Пошаговая редукция дерева
(`Lambda.Eval`) остаётся для цепочек, `:step` и `:follow`; на решении, которое
использует аргумент k раз внутри цикла по n, ей нужно порядка kⁿ шагов.

Вывод и чтение файлов — всегда UTF-8 (`Lambda.Console`): на Windows консоль
переключается на кодовую страницу 65001, а если это не удалось, символы вне кодовой
страницы заменяются, а не роняют программу.

## 8. Интерфейс

- Библиотека: `Lambda.Check.checkFile :: FilePath -> IO (Either String [TaskResult])`,
  где `TaskResult` = идентификатор, заголовок и список именованных проверок с
  `Either String ()`. `Test/Lambda.hs` шаблона превращает это в HUnit-тесты.
- CLI: `lambda check FILE` — та же таблица текстом; `lambda load FILE` — REPL
  (`:nf`, `:step`, `:follow`, `:explain`, `:type`, `:env`, `:reload`), стратегии `normal`
  (`lazy`), `strict`, `applicative`. `lambda load` без файла — пустая сессия, язык
  `pure` или `--language typed`.
